# Coin Dozer

동전을 넣고 바라보는 코인 푸셔(코인 도저) 게임. 실제 기계와 같은 강체 물리로 동작합니다.

**▶ 플레이: https://em3s.github.io/coindodger/**

```bash
npm install
npm run dev     # http://localhost:5188
npm run build   # dist/ (base 경로 /coindodger/)
```

`main`에 푸시하면 GitHub Actions가 빌드해 Pages로 배포합니다 (`.github/workflows/deploy.yml`).
다른 경로에 올리려면 `BASE_PATH=/my-path/ npm run build`.

**기본은 방치형입니다.** 딤 처리된 화면에 시계가 떠 있고, 뒤에서 기계가 자동으로 돌아갑니다.
화면을 만지면 5초간 깨어나 기계와 조작 UI가 또렷해지고, 그 뒤 다시 어두워집니다.
첫 터치는 깨우기만 하고, 깨어 있을 때 탭하면 **그 자리로 투입구가 옮겨 가고 동전이 들어갑니다.**
<kbd>Space</kbd> 투입 · <kbd>←</kbd><kbd>→</kbd> 투입구 이동 · <kbd>M</kbd> 소리 · <kbd>E</kbd> 세팅 모드.
**소리는 기본 꺼짐**입니다 — 켜두는 화면이라서요. 꺼져 있는 동안엔 오디오 컨텍스트 자체를 만들지 않습니다.
나머지(동전 추가·자동 투입·소리·상태 링크·세팅 모드)는 우상단 **⚙ 설정**에 있습니다.

**시점은 고정입니다.** 돌리거나 당길 수 없고(카메라 입력을 전부 제거), 화면비에 맞춰 반경만
자동으로 잡아 기계가 항상 크게 보이도록 합니다. 세로 화면에서 가로 93%를 채웁니다.

**동전은 자동으로 채워지지 않습니다.** 다 쓰면 설정에서 직접 추가해야 합니다.
다만 회수율이 160% 안팎이라 방치해두면 동전은 계속 늘어납니다.
깨어 있는 동안 상단에 보유·투입·획득·수익률이 보입니다.

## 스택

| | | 이유 |
|---|---|---|
| 렌더링 | **Babylon.js 9** | PBR·IBL·그림자·ACES 톤매핑·블룸·SSAO2를 엔진이 전부 제공. 직접 구현한 셰이더가 없음 |
| 물리 | **Havok Physics** (WASM) | 원래 AAA 네이티브 엔진. 얇은 원기둥 수백 개가 쌓이는 스태킹 안정성이 웹 물리엔진 중 가장 좋음 |
| 번들러 | Vite | |

게임 로직 외에는 전부 엔진 기능을 씁니다. 푸셔 구동도 직접 속도를 계산하지 않고
`PhysicsPrestepType.ACTION`으로 **목표 위치만** 주면 Havok이 필요한 속도를 역산합니다.

## 물리 설계

**단위계** — `1 unit = 10 cm`, 중력 `-98.1 unit/s²`. 실제 스케일과 물리적으로 완전히 동일하면서
물체 크기가 0.1~10 unit에 들어와 솔버 정밀도가 가장 좋은 구간에서 돕니다.
물리는 **120 Hz 고정 서브스텝**(`setSubTimeStep`)으로 프레임레이트와 분리돼 있습니다.

**투입 경로** — 화면 위에서 동전을 소환하지 않습니다. 실제 기계와 같이

```
  투입구(탭한 자리로 옮겨 가는 슬라이더)
      ▼
      ╲╲╲╲╲╲          ← 슈트: 미끄러운 경사로(마찰 0.06), 양옆에 가드레일
            ╲╲╲╲ ▐    ← 스토퍼: 전진을 끊어 제자리에 떨군다
                 ▼
        ▓▓▓▓▓▓▓▓▓▓    ← 덱 위 z ≈ -1.15 에 안착
```

슈트 전체가 착지 지점보다 **뒤쪽**에 있습니다. 카메라가 앞에 있으니 뒤쪽 물체는
원리적으로 플레이필드를 가릴 수 없습니다 — 예전엔 슈트가 화면을 가로질러 시야를 막았습니다.

동전은 투입구 입구에 **놓일 뿐**이고, 경사로를 미끄러져 내려가 뒷벽에 맞고 덱에 떨어집니다.
좌우 위치는 슬라이더가 정하고, 앞뒤 자리는 그때 푸셔가 어디 있느냐 — 즉 **타이밍**이 정합니다.

실측 (`node tools/probe-chute.mjs`): 슬라이더 양끝(±0.88)까지 착지 x 편차 ±0.04 이내,
덱 착지 z는 항상 -1.09 ~ -1.18. 경사로에 걸리는 동전 0건.

**기계 구조** — 실제 코인 푸셔와 같습니다.

```
        ┌── 뒷벽(스크레이퍼): 밑단이 떠 있어 플레이트가 그 아래로 지나간다
        │
        ▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░       ← 상단 데크 = 푸셔의 상판 (왕복)
        ███████████                 ← 푸셔 몸통, 앞면이 하단 더미를 민다
   ──────────────────────────────┐
     하단 플레이필드 (전폭)         │
                                 ▼
                              배출구      ← 코인이 나가는 곳은 여기 하나뿐
```

코인이 앞으로 나아가는 원리는 **전부 물리에서 창발**합니다. 플레이트가 후퇴할 때
고정된 뒷벽이 코인을 붙잡아, 코인이 플레이트 기준으로 앞으로 밀려납니다. 새로 투입된
코인이 더미를 밀고, 더미가 데크 앞끝을 넘으면 하단으로 떨어지고, 푸셔 앞면이 그것을
배출구 쪽으로 밉니다. 어디에도 "코인을 앞으로 옮기는" 코드는 없습니다.

**자동 평형** — 옆으로 빠지는 길이 없어서, 코인이 나가는 곳은 배출구 하나뿐입니다.
그래서 기계가 물리적으로 꽉 찰 때까지 차오르다가 "넣은 만큼 나가는" 상태로 스스로 멈춥니다.
필드 코인 150~180개에서 안정되고, 회수율은 **160% 안팎**입니다 — 손해 보는 구조가 아니라
보상 위주로 맞췄습니다.
푸셔가 하단 더미를 통째로 미는 일은 없습니다 — 마찰이 힘 사슬을 흡수하기 때문인데,
실제 기계도 같습니다. 배출은 덱에서 계속 떨어지는 코인이 앞을 밀어내며 일어납니다.
그래서 투입에서 배출까지 30초~1분의 지연이 있고, 몰아서 터집니다.

**시작 상태** — 빈 기계는 첫 배출까지 몇 분이 걸립니다. 그래서 실제 기계처럼
평형 근처(136개)로 채운 채 시작합니다.

## 이벤트

연출이 아니라 물리로 얻어내는 구조입니다.

**대형 동전** — 16~30회 투입마다 한 번 섞여 들어옵니다. 지름 6.7cm(일반 4.2cm)에
부피가 4배라 **질량도 4배**입니다. 더미에 박히면 주변을 실제로 밀어냅니다.
배출하면 5개 값을 주고 —

**코인 러시** — 대형 동전이 배출구로 떨어지면 동전 12개가 초당 6개씩 쏟아집니다.
공짜 동전이라 투입 수에는 넣지 않고, 마퀴가 빠르게 번쩍입니다.

무작위로 터지지 않습니다. 큰 동전을 앞으로 밀어내야 터지므로, 저게 언제 떨어지나
지켜보게 됩니다. 무손실 구조(옆으로 빠지는 길 없음)에 이 보상이 더해져 회수율은 **160% 안팎**, 구간별로 130~215%까지
튑니다. 동전이 줄어드는 게 아니라 늘어나는 쪽입니다.

## 세팅 모드 (영업 전 진열)

실제 운영자가 손님에게 "될 것 같은" 그림을 만들어 두는 단계를 그대로 넣었습니다.
<kbd>E</kbd> 또는 HUD의 **세팅 모드**를 누르면 푸셔가 멈추고 배출 집계가 꺼집니다.

- **필드를 클릭**하면 그 자리에 동전을 놓습니다. 같은 자리를 반복하면 쌓입니다.
- 프리셋: 기본 / 가득 / **배출 직전**(앞줄이 립 밖으로 걸쳐 한 번만 밀면 떨어짐) /
  **가장자리 아슬아슬** / **탑 쌓기**(배출구 앞에 8단 탑) / 비우기

검증 (`node tools/probe-presets.mjs`): 프리셋 배치 후 세팅 중 유실 0~9개,
탑은 무너지지 않고 서 있으며(높이 0.37), 영업 시작 후 60초·60투입에 5~17개 배출.

## 헤드리스 시뮬레이션

브라우저 없이 물리만 결정론적으로 돌려 안정성과 회수율을 검증합니다. 실시간의 약 15배 속도.

```bash
node tools/simtest.mjs 900 1.0    # 900초 분량, 1초마다 투입 — 안정성과 회수율
node tools/probe-chute.mjs        # 슈트를 탄 동전이 실제로 어디 닿는지
node tools/probe-presets.mjs      # 세팅 프리셋이 무너지지 않는지
node tools/probe-push.mjs         # 푸셔가 하단 더미에 닿는지
node tools/probe-event.mjs        # 대형 동전이 슈트를 타고 덱에 앉는지, 러시가 도는지
node tools/probe-state.mjs        # URL 저장 크기와 복원 정확도
```

```
초  | 투입  획득  회수율 | 필드  최대 | 하단/상단 슈트
270 |   90    53     59% |  149   161 | 82/67 슈트0
...
✅ 900초 시뮬 완료 — 총 투입 894, 획득 414, 회수율 46%
```

`슈트0` 은 경사로에 걸린 동전이 없다는 뜻입니다 (막힘 검사).

## 상태 저장 — URL 하나로

**현재 상태 링크** 버튼을 누르면 그 순간의 기계가 통째로 URL에 담깁니다. 링크를 열면
동전 하나하나의 위치와 자세, 지갑/획득/투입 수, 슬라이더 위치, 푸셔 위상까지 그대로 복원되고
거기서부터 이어서 굴러갑니다. 이후 전개는 물리 시뮬레이션이라 기기마다 갈라집니다.

- 코인 1개 = **11바이트** (위치 16bit×3 + 회전 32bit smallest-three + 종류 8bit)
- 정렬 + 바이트 평면 분리 → 브라우저 내장 `CompressionStream('deflate-raw')` → base64url
- 실측: 코인 137개 → URL 1,781자. 137개 기준 JSON이면 15,000자가 넘습니다.
- `#` 뒤에 두므로 서버로 전송되지 않고 길이 제한에서도 자유롭습니다.

검증 (`node tools/probe-state.mjs`): 왕복 오차 **위치 0.005mm, 자세 0.14°** — 사실상 무손실.
복원 직후 푸셔를 멈춰 3초 두면 코인 이동 중앙값 0.01mm로, 더미가 튀지 않습니다.

## 모바일

- 조준은 3D 손잡이 드래그 대신 화면 아래 슬라이더로 합니다 (데스크톱에서도 동작).
- 터치 기기(`pointer: coarse`) 또는 좁은 화면에서는 렌더 비용을 낮춥니다 —
  SSAO 끄기, 그림자 2048→1024, MSAA 끄기, 픽셀비 1.3 상한.
  **물리는 그대로 둡니다.** 그래야 기기가 달라도 같은 URL이 같은 상태를 냅니다.
- 세팅 패널은 좁은 화면에서 바텀 시트로 바뀌고, 안전영역(노치)을 피합니다.
- HUD 버튼에 `touch-action: manipulation` — 연타해도 더블탭 확대가 걸리지 않습니다
  (의도적인 핀치 확대는 남깁니다). 캔버스는 `touch-action: none`.

## 구조

```
src/config.js      모든 치수·물리 상수 (여기만 만지면 기계가 바뀝니다)
src/machine.js     캐비닛·플레이필드·푸셔·투입 슈트 지오메트리와 강체
src/coins.js       코인 풀 (GPU 인스턴싱 + 코인별 물리 셰이프)
src/game.js        게임 상태, 투입, 프리필/세팅 프리셋, 배출 판정, 푸셔 구동
src/materials.js   PBR 머티리얼과 절차적 텍스처
src/state.js       상태 ↔ URL 인코딩 (양자화·평면분리·deflate·base64url)
src/main.js        엔진·카메라·조명·포스트프로세싱·입력
tools/*.mjs        헤드리스 물리 검증 하니스 (브라우저 없이 결정론적 실행)
```

개발 중에는 콘솔에서 `__cd` 로 scene·camera·game·조명·포스트프로세싱에 바로 접근할 수 있습니다.

## 만들면서 부딪힌 것

- **트리거로 배출을 감지하면 안 됨.** 트리거 콜백은 물리 스텝 *도중*에 호출되므로 거기서
  바디를 건드리면 Havok 내부가 깨집니다. 또 트리거 볼륨 안에서 코인을 풀로 회수하면
  `TRIGGER_EXITED`가 영영 오지 않아 내부 페어 목록이 쌓입니다. 지금은 위치로 판정합니다.
- **동시 접촉 수가 한계를 넘으면 WASM이 out-of-bounds로 죽습니다.** 코인을 키우고 필드를
  줄여 동시 코인 수를 130 안팎으로 유지하고, `FIELD_CAP`(165)을 안전판으로 둡니다.
- **대형 동전은 통로에 낍니다.** 슈트 끝에 스토퍼를 두고 전진을 끊었더니, 지름 6.7cm
  동전이 3.4cm 통로에 걸렸습니다. 스토퍼를 없애고 경사를 마찰각 바로 위(5°)로 낮춰
  애초에 느리게 내려오게 바꿨습니다 — 통로가 없으면 낄 곳도 없습니다.
- **기계는 비어 있으면 안 됩니다.** 실제 기계처럼 시작부터 코인이 깔려 있어야(`prefill`)
  첫 배출까지 몇 분씩 걸리지 않습니다.
- **슈트 막이를 경사로 중앙 기준으로 놓으면 안 됩니다.** 경사로 전체를 덮는 천장이 되어
  넣은 동전이 경사로를 타지 않고 앞으로 튕겨 나갔습니다. 위끝 바로 뒤에 세워야 합니다.

## PWA — 설치와 업데이트 알림

홈 화면에 설치해 전체화면으로 쓸 수 있고, 오프라인에서도 돕니다.

- `vite-plugin-pwa`로 매니페스트와 서비스워커를 생성합니다. 프리캐시 254개 12.3MB
  (Babylon 번들과 Havok wasm이 커서 Workbox 기본 상한 2MB를 12MB로 올렸습니다).
- 아이콘은 외부 의존성 없이 순수 파이썬으로 그렸습니다 — 게임 속 코인과 같은 금색 별 문양
  (192 / 512 / maskable 512 / apple-touch 180).
- **업데이트를 몰래 갈아끼우지 않습니다.** `registerType: "prompt"`로 새 버전을 감지하면
  화면 위에 "새 버전이 있습니다 [새로고침]" 배너를 띄우고, 누를 때 적용합니다.
  딤 상태에서도 보이도록 오버레이 위에 둡니다.
- 켜둔 채 며칠 지나는 화면이라 30분마다 새 버전을 확인합니다.
- 설정 시트 맨 아래에 빌드 시각이 표시됩니다.

## 방치 모드

시계가 주인공이고 기계는 배경입니다. 전면 유리 칸막이도 없앴습니다 — 가릴 게 없습니다.

- 딤: 캔버스 위에 어두운 오버레이 한 장. 캔버스를 다시 그리지 않아 비용이 없습니다.
- 깨어남: 터치/키 입력 후 5초. 설정 시트를 열거나 세팅 모드면 계속 깨어 있습니다.
- **딤 상태에선 30fps로 그립니다.** 물리는 실시간 델타로 계속 정확히 돌아가므로
  시뮬레이션은 영향을 받지 않고, 그리기 비용만 절반이 됩니다.

## 성능 — 그래픽이 아니라 물리에 묶여 있다

M 시리즈 맥에서 코인 160개 기준 실측:

| | 물리 | 그리기 | 프레임 합 |
|---|---|---|---|
| 240Hz 서브스텝 | 10.2ms | 3.4ms | 13.6ms |
| **120Hz (현재)** | **7.2ms** | 3.4ms | **10.6ms** |
| 더미가 가라앉은 상태 | 4.2ms | 3.4ms | 7.6ms |

비용의 3/4이 물리입니다. 그래서 그래픽 품질을 낮춰봐야 별 효과가 없고,
**서브스텝 수가 곧 배터리**입니다. 240 → 120Hz로 낮췄을 때 회수율(151%→149%)과
안정성이 그대로였고, 오히려 가라앉은 더미의 떨림이 0.25mm → 0.12mm로 줄었습니다
(`node tools/probe-jitter.mjs 120`).

가라앉은 코인은 Havok이 재우므로, 가만히 두면 물리 비용이 4.2ms로 떨어집니다.
탭을 숨기면 rAF가 멈춰 0이 됩니다.

더 줄여야 하면 순서대로: 90Hz 서브스텝(-16%, 대신 빠른 코인이 얇은 바닥을 뚫을 위험),
`FIELD_CAP` 낮추기(접촉 수에 비례), 렌더 해상도 상한 낮추기.
